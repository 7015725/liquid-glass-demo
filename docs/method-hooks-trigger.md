# 方法钩子触发器（alpha21）

## 规则里的入口

新增内置触发器 `trigger.method_hook`（分类「应用」，仅 Xposed 层）。参数只有 `hook`：
从设置页已创建的方法钩子列表里点选，显示 `包名@用户ID`、`类名#方法名` 和启用状态。
不能再手填标识；列表为空时提供「去新建方法钩子」入口。规则匹配到目标进程上报的
`hook.id` 才执行，不会把同一目标应用的其他方法调用混进来。

流程：

1. 设置 → 方法钩子 → 新增：目标包名、用户 ID、类名、方法名、可选参数个数/参数类型、
   提取项。保存时按全局变量名校验，重名或占用内置名直接拒绝。
2. 目标应用在 LSPosed 作用域勾选，重启目标进程；LSPosed 入口在 `Application#attach` 后安装。
3. 规则添加「方法钩子」触发器，从下拉列表选择已创建的钩子。
4. 方法被调用（原方法返回后）由目标进程通过已校验的 Binder 通道上报；`TriggerHost` 把事件
   交给 `TriggerDispatcher`，匹配规则并执行。

## 变量

固定字段现在属于 `trigger.app_method_call` 的输出 schema，默认名如下（均只读）：

- `{调用应用}`：目标包名
- `{调用用户}`：Android 用户 ID
- `{调用进程}`：实际触发进程名
- `{调用方法}`：`类名#方法名`
- `{调用签名}`：收敛后的参数签名
- `{调用标识}`：钩子标识

用户在提取项里起的中文名（如 `{订单号}`）是同一触发器的**动态输出**，不再加
`event.hook.` 前缀。值只读、截断 512 字符；字段路径只允许声明式字段名，不在目标进程执行脚本。

输出页把固定字段显示为可改名/可禁用的行，把提取项显示为只读列表，并提供「去配置提取数据」
返回现有编辑器。两者都进入运行期只读名单，脚本和「设置变量」不能覆盖。完整规则见
[`docs/output-variables.md`](output-variables.md)。

保存钩子时仍会与已有局部、全局、内置、其他输出和提取名比较，重名会被拒绝。

## 设置页

设置主页新增「方法钩子」入口。页面显示：

- 已配置钩子数量、启用状态（新建钩子默认关闭，需要单独打开）；
- 每个钩子的安装结果（按进程）：`已安装` / `未安装` / `未上报`；
- 新增/编辑/删除、启用切换、提取项编辑；
- 信任边界说明：勾选作用域即表示信任目标应用；同 UID 代码理论上可读自己的 token，
  本机制防止其他应用伪造和重放，不做同 UID 密码学隔离；第一版只读。

## 测试

- engine：`TriggerEngineTest.methodHookMatchesItsHookAndExposesRawVariables`
  验证 hook 精确匹配、原始中文变量进入执行变量表。
- 变量目录：`VariableManagerTest.methodHookExtractionsAreOutputsAndCannotBeReused`
  验证提取变量登记为输出、带中文说明，并拒绝与全局变量重名。
- 组件/参数矩阵：组件 64、参数 87；旧版迁移矩阵显式排除 alpha21 新组件。
- 设置页 UI 仅编译与元数据测试，按用户要求不做模拟器测试、不截图。
