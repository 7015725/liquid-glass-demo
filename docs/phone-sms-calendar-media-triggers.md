# 电话、短信、日历与媒体触发器

本页说明 M3 新增的六类触发器，以及“收到通知”触发器的字段扩展。所有触发器都是**事件型**：ALL 模式只判断时间窗口内是否发生过，不读取当前状态作为替代。

## 通话状态与未接来电

| 触发器 | 事件参数 | 权限 |
| --- | --- | --- |
| 通话状态 | `ringing`、`offhook`、`idle`、`any` | 电话状态 |
| 未接来电 | 无 | 电话状态 |

- 电话状态权限对应系统的“电话”权限（`READ_PHONE_STATE`）。
- 响铃 → 接通不会产生未接来电；响铃 → 空闲会产生一次未接来电。
- 未接来电只根据状态边沿推断，不读取通话记录，因此无法区分“未接”和“用户拒接”。
- 通话状态输出 `通话状态`，值为 `ringing`、`offhook` 或 `idle`。
- 部分双卡设备会把两张卡的状态合并上报；本版本不提供卡槽区分。

## 收到短信

- 权限：接收短信（`RECEIVE_SMS`）。
- 只读取系统投递的这一条新短信，不读取历史收件箱，也不读取彩信附件。
- 可选“发送方”精确匹配号码；可选“正文关键字”。关键字默认按不区分大小写的**字面量子串**匹配，也可以切换为**精确**或**正则表达式**。
- 正则使用大小写不敏感匹配；保存时会拒绝无效表达式和超过 512 字符的表达式。正则只作用于正文，发送方始终精确匹配。
- 输出 `短信发送方`、`短信内容`。
- 长短信会按系统投递的分片拼接正文；发送方以第一片的来源号码为准。

## 通知字段扩展与通知已移除

“收到通知”新增以下可选过滤字段：

- 副文本关键字
- 类别（例如 `msg`、`email`、`call`）
- 渠道 ID
- 常驻通知（任意 / 是 / 否）
- 关键字匹配方式（包含 / 正则）

标题、正文、副文本默认按不区分大小写的字面量子串匹配；也可切换为“精确”或“正则”，后两者都按大小写不敏感方式比较。类别、渠道和应用始终按精确值匹配。正则保存时会拒绝无效表达式和超过 512 字符的表达式；包含 `|` 的正则会被无损存成结构化参数，不会破坏字段分隔。

新增输出：`通知副文本`、`通知类别`、`通知渠道`、`常驻标记`。

“通知已移除”在用户清除通知、应用取消通知或系统移除通知时触发，可按应用、标题、正文、副文本、类别、渠道、常驻状态过滤，并使用与“收到通知”相同的关键字匹配方式。

- 两者都依赖“通知使用权”，由用户在系统设置中授予。
- 同一应用更新已有通知可能再次产生“收到通知”，本版本不额外区分更新与新通知。
- 应用自身的常驻前台通知被明确排除，避免规则自触发循环。
- 旧规则只保存了应用/标题/正文三个字段；打开旧规则时新增字段自动填入默认值，不会被当成未知组件。旧的七字段通知规则同样会补齐“关键字匹配方式=包含”。

## 媒体曲目变化

- 依赖“通知使用权”，用于读取当前媒体会话。
- 可选“应用”精确匹配媒体应用包名；留空匹配任意媒体应用。
- 输出 `曲目标题`、`艺术家`、`专辑`、`媒体应用`。
- 只在媒体元数据变化时触发；开启规则本身不会补发当前曲目。
- 不控制播放、不读取音频内容，也不读取媒体文件。

## 日历变更

- 权限：读取日历（`READ_CALENDAR`）。
- 监听日历事件表的新增、修改和删除；不读取或输出事件标题、参与人、地点、描述。
- 日历提供方可能把一次修改合并成多次变更通知，规则仍受 2 秒全局防抖约束。
- 部分厂商日历不实现标准变更通知，此时触发器可能不工作；这是提供方行为，不是规则错误。

## 权限与降级

- 缺少电话状态权限时，通话状态和未接来电规则不会注册监听，状态页显示“缺少权限”。
- 缺少接收短信权限时，系统不会向应用投递短信广播。
- 缺少日历权限时，日历监听器不会注册。
- 缺少通知使用权时，通知、通知已移除和媒体曲目变化都不会注册；不会用轮询或无障碍服务绕过系统限制。
- 所有监听只在存在启用规则时安装；关闭规则或暂停引擎会释放监听器。
