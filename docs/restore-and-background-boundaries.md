# 恢复、后台与草稿的边界

## 恢复备份不等于授权执行（STO-01）

从备份恢复会替换指令、变量与外观设置，但不会继承文件里的执行授权：

- 引擎运行状态强制为关闭，所有自动指令的 `enabled` 强制为 `false`；恢复完成后由用户逐条开启。
- 备份中的 `keepalive.fgs`、`keepalive.boot`、`keepalive.job` 与 `system_hook.enabled` 不再自动应用，
  需要在设置页手动打开。
- 恢复前仍会写一份当前数据的安全副本；恢复失败不会发布新状态。

## 未保存的组件草稿（STO-14）

进程被系统回收后，导航只能恢复已保存组件的 ID。新建但未按「完成」的草稿没有稳定 ID，无法恢复；
恢复动作页时会提示「未保存的组件草稿已丢失，已恢复上次保存的版本」，不会把导航恢复呈现为草稿已恢复。

## 后台钩子事件（TRG-003）

Android 12+ 在应用后台可能拒绝启动前台服务。系统钩子事件启动失败时不再丢弃，而是写入最多 32 条的
本地队列；下一次服务被允许启动（回到前台、开机、闹钟）时按到达顺序补投。队列只保留最近 32 条，
更早的事件被淘汰。
